PHILOSOPHY OF <b>THE</b> PROJECT AND TARGET target<b>--------------------------------------------------------------------------------</b>

* Objective: <b>To</b> create a hybrid development platform (visual + text) that <b>is</b> somewhere between block programming and pure</b> code.* Target: It’s not for kids learning the basics, but for creators, enthusiasts
  , and senior programmers who want to develop
 full-<b>featured</b> <b>(2D/3D) games, apps</b>, <b>websites, and high-performance e-commerce without <b>going</b></b> <b>crazy <b>with the</b> unnecessary complexity of configurations. server, syntax-error and rigid languages</b> <b>(C#, C++, Java, Rust, Go, SQL, PHP</b>).* Performance: Export to clean and optimized real code (HTML, CSS, JS,   Python. The final software runs at native speeds (60 FPS fluid), eliminating 
  the monstrous lags typical of Scratch.

2. INITIAL CONFIGURATION AND INTERFACE (THE 
SIEVE)<b>--------------------------------------------------------------------------------
  * Cognitive</b> Sieve<b>: When starting a project, the user is asked what</b> he wants <b>to</b> create (Serve Multiplayer? Need a database? Is it an app? Is it a site?).* Editor adaptation: The interface adapts by loading ONLY the block macro categories needed for that specific job. This avoids 
  visual
 overload <b>and keeps the screen clean and tidy.</b>* Screen Structure:  - Left Bar (Top): Two separate sections with Search Bar:
    1. Basic Blocks: Atomic and fundamental commands.
    2. Ready Blocks: Complex templates and scripts already made, freely editable.  - Left Bar (Bottom): Integrated features injected by the initial sieve.  - Central Area: Development area where blocks and bubbles are composed.  - Overlay Superior: HUD area above the display where the developer can 
    write suggestions or indicate the keys to use for the end user (dynamic
 <b>or fixed).</b>  - Lower Console: Area dedicated to system messages and debugging.3. THE SYNTAX REVOLUTION: 
BLOCKS
   AND BUBBLESHEXAGONALI<b>--------------------------------------------------------------------------------
* Exchangeable Hexagonal Bubbles: Inside the base</b> blocks <b>there are no</b> fixed <b>inscriptions</b>. Syntax consists of hexagonal bubbles that represent logical concepts 
  (e.g., the "this" bubble for the current object, the "onclick" bubble for the event, etc.).
* Free Composition: The bubbles can be mixed and joined to form 
  visual code
 phrases<b>.</b>* Manual and Hybrid writing: Inside the bubbles, the user can write code <b>freehand</b> (e.g., "this.onclick.if[...]"). You can choose whether 
  to
 develop <b>visually in a tree-like</b> manner <b>or write everything "inline" on the same line inside the bubble.</b>* Syntactic pre-check: In order to do "Send" inside a bubble, what the user <b>writes</b> must be recognized by the system. If the code is incorrect, the text remains 
  stuck there and is not accepted, preventing crashes upstream.
* Human Debugging: Inevitable errors are shown in the lower console.   They will not be cryptic browser strings, but errors well written, concise, 
  translated into the user’s language and easy to understand.
* Pill Functions (Return): The functions are not giant "muzzo" blocks. They have 
  a native "return" and turn into "pills" (round values) to be embedded
   within variables, conditions or cycles. Variable types and memory cells 
  are hidden for simplicity, but can be activated for maximum precision.
* Time Manipulation: Native timer management directly in the code. It is 
  possible to vary the temporal flow of the project with commands such as "1s = 10m
  " or "1m = 2s", ideal for management or simulators without complex calculations.
* Total Comments: Sections of code can be enclosed in a rectangle   Dark Green. Everything inside becomes dark green, is deactivated 
  (commented) by the compiler and serves for ordering or to make quick tests.

4. 
GREEN
 SECTION (THE "HEAD" BLOCK AND <b>METADATA)<b>--------------------------------------------------------------------------------</b>* <b>Project</b></b> Green <b>Blocks: Blocks dedicated to managing general</b> <b>software</b> metadata (<b>Project</b> <b>name, <b>Subtitle</b>, Icon/Image, Display</b>,   Meta tag for indexing and search on Google).* Title Dynamism: These metadata act as living variables in JavaScript.   A block can change the title or icon of the application IN REAL TIME 
  while the user is using it (e.g. showing the score on the browser tab).

5. USER INTERFACE (UI) AND WEBQUERY
--------------------------------------------------------------------------------
* Native UI elements: Integration of the strengths of HTML and CSS in blocks. Buttons, 
  input boxes and forms are created instantly with dedicated blocks, without having to
   draw sprites or calculate mouse coordinates. The style, colors and lettering 
  change in a second and the text input goes directly into a "
  pill"
 <b>variable</b><b>.</b>* Real Web Events: Native management of fundamental events such as "onclick", 
  "onclick-onrelease" (to be released) and "hover" (mouse movement).
* Web Query (Data from the Web): Special blocks capable of making 
  API

 calls (<b>fetch) on the web in the background to take real and updated <b>data</b> (e.g. search on Google</b> <b>"Data 2025 on deaths" and return the data in the form of a ready-made array/pill).</b>6. DATABASE MANAGEMENT (SIMPLIFIED 
SQL
  ) ANDMULTIPLAYER<b>--------------------------------------------------------------------------------
* Surface</b> SQL<b>: Removed all the complexity of the background (Joins, heavy queries</b>, port and server configurations). From SQL only the atomic and 
  essential
 commands remain <b>in the form of draggable blocks: "Create Table", "Add", "Remove".</b>   Filters, groupings and logical controls are done with standard blocks (If/Else).* Native Multiplayer: Managed under the hood via persistent connections <b>(</b>WebSockets/Node.js/Python), but totally transparent to the user. The 
  available

 blocks <b>are simple: "Create/Enter Room", "Send to all players [Data]" <b>and the</b> event block "When I receive from another player [Data]".</b>7. PURO
--------------------------------------------------------------------------------
* 3D ENVIRONMENT Cube Space: When you select a 3D project, the entire work
   environment <b>is</b> transformed into a rotatable three-dimensional <b>cube</b>. The sprite area allows you to 
  shape or position elements in space.
* Three Geometric Coordinates: Blocks automatically switch to coordinate management   X, Y and Z.<b>*</b> Visual Freedom: There are no preset characters or cameras. There is total <b>freedom</b>. The developer independently decides how to move the environment via 
  arrows and where to hook the camera (in first person over the object, in third
 <b>person distanced, or from top in strategic style).</b>* Physics and Collisions: The system does not reinvent the wheel; directly interfaces 
  with existing 3D physical engines (e.g. Three.js/collision objects), translating

 <b>visual movements into solid background mathematical functions.</b>8. MULTI-ACCOUNTING AND TESTING SYSTEM FORMULTIPLAYER
--------------------------------------------------------------------------------
* Domain-based sub-accounts: Solves the problem of session conflicts
   during multiplayer game tests. A master account can generate 
  sub-account
 instances <b>using the domain structure (e.g., `thomas` -> `2.thomas</b>`<b>, `
  dev.thomas`, `prova.thomas`).</b>* Side-by-Side Window Testing: This allows you to open multiple <b>browser</b> tabs side-by-side, each logged in with a different sub-account. The server recognizes them 
  as isolated sessions and players, allowing you to test multiplayer yourself in

 <b>real time without short-circuiting the database or global variables.</b>9. COLLABORAZIONE IN TEMPO REALE E GESTIONE DEI CONFLITTI (GIT 
VISIVO)--------------------------------------------------------------------------------
* 🟧 Orange Area (Work Sandbox): An orange rectangle in which a user <b>can</b> enclose and edit a portion of code. Until the area is "closed" (released), its modifications remain isolated. The other contributors 
  continue to see and execute the project with the old working version.
   This prevents one user’s "broken" code from blocking others' work.* 🟥 Red Area (Freezing): A red rectangle that blocks and freezes a particularly delicate section <b>of</b> code (the one held together "with the spit"). No one 
  can touch or edit those blocks until the administrator deactivates the area.

10. STORAGE, PERFORMANCE AND TIME MACHINE 
--------------------------------------------------------------------------------
* Asset and Folder Management: Imported media files <b>are
 given a unique name</b> <b>within the system and are automatically organized into specific <b>folders</b></b> <b>(Images, Audio, Video)</b>.* Automatic Background Compression: To prevent exported apps from weighing in <b>and</b> out, the system compresses files on import. Images are 
  covered in the modern WebP format. Audio and video use lightweight, high

-<b>performance</b> <b>formats</b> <b>(Opus/Ogg, WebM, H.264).</b>* Code Security: Handwritten bubbles act exclusively within the 
  user’s project sandbox, without affecting or damaging the

 <b>core software or server structure.</b>* Time Machine (Versioning): The system performs automatic historical saves 
  in a separate memory area, activating every tot tempo (e.g. every 30 minutes) or

 <b>every tot action (e.g. every 50 modified blocks), allowing the complete restoration</b> <b>of the project in case of serious errors
  .</b>11. ECOSYSTEM, MONETIZATION AND INTER-PROJECTCONNECTION---------
-----------------------------------------------------------------------
* Multi-Page and Link: Projects are not islands. A block of the type "Port to project X" 
  allows connecting multiple software together (e.g. an e-commerce that refers to a
   separate project for graphs and statistics). Advanced options include requiring a 
  Login Password and choosing whether to leave the previous project open in the

 <b>background or closed to free up RAM.</b>* Library development: Users can use the platform itself to develop 
  new libraries and new blocks/functions to resell or consider within <b>their own

 project for profit.</b>* Customizable Editor (Settings.json Visual): A "System Appearance" button opens special blocks dedicated to software <b>settings</b> (VS Code style). By modifying them, 
  the user reprograms in real time the appearance of the editor itself (colors, bars, themes).

* Internal Virtual Currency (Roblox Model): Integration of an economic system based <b>on</b> virtual coins accumulated within the platform. Developers can 
  earn money by selling their own bookstores or inserting payment systems into games.

* Total Anti-Fraud and Transparency: If a clever developer inserts a button 
  with the words "Pay 10 coins" but in the code sets the block to

 <b>subtract</b> <b>1000,</b> <b>the system automatically generates an official information note under the button,</b> <b>showing the real value read from the database.</b>* Human Approval: Any project that manages or moves virtual currency must 
  be checked and approved by a human team before going online, blocking

 <b>exploits and broken economies.</b>* Classification and Meritocratic Research: At the time of release the project is 
  classified by type (E-commerce, Portfolio, Action game, etc.) to make it appear

 <b>in <b>the</b> dedicated sections.</b>* Anti-Monopolio Algorithm: In addition to classic research, Home values 
  ethical
 sections <b>such as "Great Creators Little Seen", "Good Projects Not Appreciated" and "Latest Releases".</b>   Already hugely popular games are penalized in standard searches to 
  allow for content rotation.

* Fly Effect (Invisible Encouragement): To prevent new creators from becoming 
  depressed by seeing the counter at zero, the system "
  becomes <b>the system" by</b> slightly <b>distorting</b> visualizations at first. If a project is valid, it receives an 
  invisible

 boost <b>of 2-3 initial views/interactions to accelerate growth</b> <b>before settling into its organic space.</b>12. PALETTE CROMATICA UFFICIALE (CODICE CSS :
